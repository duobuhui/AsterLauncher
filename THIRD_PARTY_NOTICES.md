# Upstream research and release notices

Beta 0.1.0 release tooling follows [GitHub's Releases REST API](https://docs.github.com/en/rest/releases/releases) for listing releases and assets. The `latest` endpoint excludes prereleases, so the launcher uses the releases list to find beta versions. This is API documentation under GitHub's site terms; no GitHub sample code or assets were copied. The public source and ZIP include the attributed publisher media below after the project owner confirmed redistribution authorization on 2026-09-24; the images are not relicensed by any source-code license.

This ledger records every upstream project or document used as a technical reference for AsterLauncher. A reference entry does not mean that upstream code, branding, UI, or artwork was copied. Before a public release, re-check the linked revision, bundle the required license texts for redistributed components, and review game-media redistribution rights separately from source-code licenses.

Endfield authorization URLs contain credentials. AsterLauncher never logs, persists, or displays those URLs or tokens. The capture implementation reads only this explicit cache file, permits only the verified CN host and the upstream-documented global host `ef-webview.gryphline.com`, requests only `/api/record/char` and `/api/record/weapon`, and writes the resulting record data only to the project-configured data directory. The real token was not printed or copied into a fixture. An earlier isolated HTTP probe could not complete TLS authentication; a user-authorized controlled request on 2026-09-24 then confirmed a successful official response when the first-page request omitted `seq_id`. The isolated WinUI sync then saved 420 character records on 2026-09-24; its archive contained no token or authorization URL fields.

## Release checklist

1. Freeze the upstream URLs and revisions used by the release.
2. Re-check every license and include required notices/license text for redistributed code or binaries.
3. Audit `Assets/Games` against `ASSET_SOURCES.md`; source-code licenses do not grant game-art rights.
4. Confirm that no authentication URL, token, account identifier, or private log is included in logs, telemetry, screenshots, or fixtures.
5. Keep the Starward attribution as a product reference only unless future code reuse is explicitly approved and recorded.
