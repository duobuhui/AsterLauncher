# 游戏资料

客户端读取 [catalog.json](catalog.json)，与启动器版本更新独立。资料来自官方可核实的公开来源，修改后增加 `revision`，合并到 main 生效。资源只用于展示，不包含可执行代码、游戏补丁或账号数据。

## 卡池与图片

- 卡池使用稳定的 `gameId + key + phase`，包含展示名称、边界时间、对应武器池和官方公告来源。终末地新池可填写 `category`（chartered / refactor）和 `featuredOperator`；重构池必须填写明确的 `phase`。未核实的规则留空，未知池继续保守处理。`version` 可标注官方已确认的版本归属，不根据日期猜测。
- 图片使用 PNG、JPEG、WebP，提供 SHA-256、大小、来源及权利说明。文件放在本目录，单张最多 8 MiB，总计最多 64 MiB；仅缓存到启动器数据目录，不在打开记录页时下载。新增素材同时维护 [ASSET_SOURCES.md](../ASSET_SOURCES.md)。

## 终末地版本日历

客户端 0.2.1-beta 起，终末地日历合并 `pools` 与 `announcements`。每条公告包含 `gameId`、稳定的 `key`、`kind`、`title`、官方 `url`、`region`、`platforms` 及开始边界；可选 `version`、简短 `description` 和结束边界。

| `kind` | 展示类别 |
| --- | --- |
| `event` | 活动 |
| `version` | 版本更新 |
| `maintenance` | 维护 |
| `livestream` | 前瞻 |

公告必须有已核实的开始时间或日期；未公布开始边界的消息暂不放入日历。结束边界未公布时留空，客户端仅在已知开始日展示，不向后填满所有日期。`region` 使用 `CN` 表示国服，明确适用全部地区时才使用 `all`；`platforms` 可填写 `PC`、`Windows` 或已确认的其他平台，明确全平台时使用 `all`。空平台列表表示来源未注明，界面不会将其描述为已确认全平台。当前入口仅在终末地提供，其他游戏的界面适配另行实现。

## 兑换码

`codes` 每项填写 `gameId`、`code`、`reward`、官方 `source`、`region` 和 `platforms`；可选 `version`、开始边界与到期边界。同游戏、同地区的兑换码不可重复。只收录能核对官方来源的公开兑换码，不填示例码、猜测码或用户专属码。

界面显示奖励、范围、已公布有效期和官方来源，并提供复制操作；已经过期的代码收在折叠区。未公布到期时间时明确标注，不据此认定永久有效；尚未到期也不代表用户已经满足兑换条件。没有已核实的未过期兑换码时保留空状态。代码清单随资料更新，客户端不读取凭据、不自动兑换、不记录兑换成功状态。

## 日期精度与发布顺序

时间统一使用带时区的 ISO 8601，客户端以北京时间（UTC+8）展示：

- 卡池与公告：完整时间使用 `startsAt` / `endsAt`；仅公布日期使用 `startsOn` / `endsOn`（`YYYY-MM-DD`）。
- 兑换码：完整时间使用 `startsAt` / `expiresAt`；仅公布日期使用 `startsOn` / `expiresOn`。
- 同一个边界不能同时填写时间和日期，未公布的边界填 null。若任一边界只有日期，整个范围统一展示日期精度，不为版本维护编造小时。日期边界当天显示“时间未公布”，不当作零点已经开始或结束。

卡池日期精度需要 0.2.0-beta.1 或更新客户端，日历与兑换码的新字段需要 0.2.1-beta 或更新客户端。新增资料字段时，**先发布兼容客户端，再提高公开资料 revision**。旧客户端写入缓存可能丢弃未知字段却保留 revision；升级后需要更高 revision 重新取得完整资料，不能修改同 revision 内容或静默清除用户数据。

客户端启动时可自动检查，也可手动刷新。资料及图片经过校验才启用；断网或更新失败时继续使用已验证缓存或随包资料。

图片权利归原发行商，本仓库源码许可证不授予图片使用权。不要提交账号信息、授权地址、Token 或签名下载链接。
