# AsterLauncher

独立开发的 Windows 游戏启动器，使用 .NET 10、Windows App SDK 2.4 和 WinUI 3。当前版本：**0.2.3**。

[下载](https://github.com/duobuhui/AsterLauncher/releases) · [反馈问题](https://github.com/duobuhui/AsterLauncher/issues)

## 安装与使用

下载 Windows x64 完整包，解压后运行顶层 `AsterLauncher.exe`。请完整保留 `App` 和 `MigrationTools` 文件夹，不要在压缩包内运行。

首次启动可查找已有游戏，也可手动选择游戏程序。设置中的游戏下载目录用于新安装；每个游戏的路径可在启动按钮右侧的展开面板中调整。

配置、日志、抽卡记录和缓存默认保存在程序旁的 `Data` 文件夹，可在设置中迁移。备份时请同时保留数据目录和 `asterlauncher.data-location.json`（如有）。

配置读取失败时会停止写入并显示恢复入口，不会重新进入欢迎页覆盖记录。每次正常保存保留一份有效配置备份；设置 → 窗口与路径 → 记录恢复，可预览并恢复配置备份，或从本地日志补回已完成的游戏时长。旧版本已经覆盖的配置无法凭空找回；缺少日志的会话不会估算，重复恢复不会重复累计。

### 官方云游戏与模拟器

右键终末地、原神、星穹铁道或绝区零，在“服务器”中选择“官方云游戏”，再点击“启动游戏”。启动器不下载游戏，确认后由默认浏览器打开官方入口；本地官服/B服的路径、方案和下载任务保留。原神与星穹铁道支持浏览器云游戏；终末地网页版计划于 2026 年 10 月 15 日开放；绝区零当前官网提供轻量云客户端，实际支持情况以官网为准。

明日方舟右键菜单可选择“启动模拟器”并指定模拟器 EXE，也可通过“选择模拟器 EXE”更换路径。启动器只打开模拟器，不自动进入游戏。云游戏和模拟器入口不统计游戏时长，也不执行本地游戏的伴随方案。

云游戏的抽卡同步使用你主动粘贴的官方记录链接，不读取本地游戏的旧缓存。授权链接只在本次同步的内存中使用；拿不到链接时可导入档案，或切回本地客户端同步。终末地角色与武器链接分别同步对应分组。浏览器跳转均需再次确认，可取消。

### 启动方案与伴随工具

在启动方案中添加工具、参数及执行顺序，可安排在游戏启动前、启动后或退出后运行。伴随工具需要自行安装，再选择对应程序路径。

### 抽卡记录

终末地、原神、星穹铁道、绝区零可在抽卡记录页面同步、导入和导出记录。这四款游戏默认增量同步，遇到已有记录后停止读取更早页面；全量同步用于补齐历史。同步需要先在游戏内打开记录页面，产生有效的本地授权缓存。原神、星穹铁道、绝区零按账号和卡池显示稀有度统计、出货间隔及本地保底计数，角色和装备图片随包内置。原神两种角色活动祈愿合并计数，其他卡池各自统计；历史记录缺失时计数可能不完整，特殊卡池不推断未知规则或 UP。

“统计详情”按账号与卡池查看出货散点、平均值、中位数和稀有度占比。原神、星穹铁道、绝区零分别绘制高稀有度与 UP 出货散点；相同抽数显示在同一位置，点击圆点可查看全部记录；历史缺失不计入完整间隔均值。无法确定 UP 的记录可手动校对，终末地目前只提供汇总统计。

点击游戏页上的时长，可按年份查看每日游玩热力表。旧版只有累计值的时长仍保留在总计中。

### 外观与游戏资料

设置中的“卡片明暗”和“主题颜色”分别保存。界面使用 Windows 自带的微软雅黑 UI 字体。游戏资料默认在启动时从本项目的公开 [资源目录](resources/README.md) 检查更新；卡池名称、时间及图片，以及终末地的版本日历和兑换码，可独立更新，无需下载启动器新版本。断网时使用缓存或内置资料，也可在设置中关闭自动检查或手动更新。

### 本地存储

设置中的“本地存储”可扫描下载缓存、旧游戏资料图片、日志、云壁纸、更新暂存和已识别的旧数据目录。先查看文件列表，再勾选删除；旧数据可能包含配置和抽卡档案，请确认已迁移或备份。当前配置、档案、游戏文件及任务正在引用的缓存会保留。删除后会一并移除空目录，遗留的空暂存目录也可单独扫描删除。

### 米哈游游戏（Beta）

原神、星穹铁道、绝区零提供国服官服与哔哩哔哩服的下载、更新、预下载和修复入口。右键游戏，在“服务器”中切换；两服分别保存目录、版本、下载任务和启动方案。崩坏3桌面端在游戏内选择服务器，使用同一套下载入口。进入游戏页检查官方版本；主按钮用于下载、继续任务、更新或启动，箭头展开后可更改目录、选择语音及检查文件。首次下载先确认安装目录、语音和资源复用选项，确认后创建目录并检查文件。

下载使用官方当前分支的文件与分块清单，支持实时进度、速度、暂停续传和重启恢复。任务卡片分别显示文件校验、另一服资源复用、下载和应用进度；复用前需读取另一服资源，大型游戏可能耗时较久。校验时显示当前文件和已处理量，下载速度只计算新传输的数据。更新按目标清单同步变化的文件，暂未使用 HDiff / LDiff 差分补丁。修复仅补齐缺失或损坏文件；安装版本较旧时请先更新。取消任务会删除此任务的缓存，已应用但未完成的更新需继续维护后才能启动；完成任务也会清理缓存，预下载及其他任务仍引用的内容保留。

预下载仅在官方开放时可用，不提前改动已安装版本，正式更新按内容哈希复用缓存。语音默认中文，可勾选其他语言；取消勾选不会删除已安装的语音。旧安装未记录渠道时保留为“未确认”；在“游戏设置 → 安装服务器”中选择原 EXE 并确认所属服务器；已有可信渠道信息与选择冲突时会拒绝保存。国际服仍需使用对应官方启动器维护。星布谷地已接入资源检查，官方尚未提供公开 PC 下载分支时显示“未开放下载”。

两服在同卷 NTFS 上可复用已校验且符合共享规则的资源包，登录组件、配置和运行时缓存保持独立。展开面板的“更多”可扫描共享情况、优化存储或解除共享。跨卷或不支持硬链接时使用独立文件；使用官方启动器维护前，请关闭两服游戏并解除共享。

### 终末地（Beta）

右键点击游戏列表中的终末地，在“服务器”菜单切换官服或 B服。两服使用独立安装目录，分别保存版本、任务和启动方案；下载任务不会因切服而转移。

进入游戏页面时检查更新。有更新时主按钮显示“更新游戏”，下载时显示实时进度、已下载量和速度。暂停保留续传，安装完成或取消任务后清理本次下载缓存；仍被另一任务引用的共用缓存保留。文件检查、修复、预下载和共享管理位于展开面板；预下载仅在官方开放时可用。

资源共享要求同卷 NTFS，仅共享符合规则且内容一致的资源。使用官方启动器维护前，请关闭两服游戏并解除共享。HDiff/VFS 原生增量目前使用目标清单逐文件同步回退。

终末地的“游戏设置”可读取和修改分辨率、切换窗口模式，以及保存、应用三个画质方案。画质先在游戏内调整，退出后在启动器中保存。画面设置由两服共用；修改前关闭游戏，原值保留用于撤销。下方可查看游戏照片，也可为各渠道选择展示文件夹。

抽卡卡片以北京时间显示卡池开放日期和对应专武申领记录。武器按件数统计，一次申领包含 10 件；角色与武器分别计数，重构申领按期分开。未收录的卡池不会推测日期或专武。
游戏页的“版本日历”默认显示横向时间轴：左侧直接列出卡池和活动名称，右侧用横条对照当月日期，今日线与跨月标记帮助查看重叠安排。可切换月份、返回今天、按类别筛选及打开官方公告，也可切换到月历查看某一天的详情。时间轴按日展示，时间统一使用北京时间（UTC+8）；官方只公布日期时保留日期精度，结束时间未公布的安排只标出起始点，不推算持续时长。

同页兑换码卡片显示奖励、适用范围、有效期和官方来源，可一键复制后在游戏支持的兑换入口使用；过期内容收在折叠区。当前没有已核实的有效兑换码时显示空状态，后续随资料更新补充。日历和兑换码目前仅适配终末地，无需读取账号凭据；兑换结果以游戏为准。点击“更新资料”可刷新，断网时保留缓存或随包资料。

### 启动器更新

在设置中检查新版本。当前版本与差量包基线完全一致、且本地文件校验通过时使用文件差量；跨过多个版本或本地文件不一致时，直接下载最新完整包，不逐版安装补丁。0.2.3 的差量基线为 0.2.2。

更新成功后自动清理暂存文件，只保留最近一次成功更新前的程序备份；旧版本留下的、可确认属于成功更新的历史程序备份也会自动整理。配置、抽卡档案和数据目录不参与程序备份轮换；失败或中断的更新保留恢复信息。

0.2.2 起不再单独提供迁移工具下载。完整包中的 `MigrationTools` 是启动与更新需要的内置组件，请保留。0.1.2 及更早的单文件版本，请将完整包解压到新目录，关闭旧版后，将原数据目录及数据位置文件复制到新目录中的对应位置；确认新版本数据正常前，请保留旧安装。

## 完整支持一款游戏需要哪些功能

欢迎通过 Pull Request 补充游戏适配。下表是完整支持的目标，当前内置游戏不一定具备全部功能；提交时请写明支持的游戏、渠道和暂未实现的部分。

| 功能 | 需要实现的内容 |
| --- | --- |
| 游戏信息与素材 | 游戏名称、官网、图标及版本主视觉；保留离线回退，注明素材来源与使用权利。 |
| 安装识别 | 手动选择、可信路径或官方配置查找、本地版本识别；处理多份安装和目录移动，不能仅凭 EXE 文件名判断渠道。 |
| 渠道与服务器 | 独立保存各渠道的路径、版本、任务和启动方案；切换后立即更新图标与按钮状态，异步结果不能串服。 |
| 下载与更新 | 使用官方实时清单和地址，支持进度、暂停/续传、重启恢复、校验、空间检查和失败恢复。更新完成后才写入新版本。 |
| 预下载与修复 | 预下载不修改当前安装，正式更新核对后复用缓存；修复检查大小和内容哈希，仅补齐问题文件，不删除用户文件。 |
| 启动与伴随工具 | 正确的入口、参数、工作目录、进程与退出检测；接入现有启动编排，保留工具执行顺序和进程所有权。 |
| 抽卡记录（如适用） | 安全同步、导入、合并去重、导出和卡池分析与出货统计；遵循适用的交换格式，不保存或记录授权 URL、Token。 |
| 资源共享（如适用） | 两服独立目录，仅共享确认不可变的相同资源；写入先生成独立文件再替换，支持解除共享和不支持硬链接时的回退。 |
| 游戏设置与照片（如适用） | 读取真实设置，修改前检查游戏进程并保留原值；只操作确认过的设置项。展示游戏截图，保留原文件。 |
| 界面与兼容性 | 沿用现有控件和布局，显示清楚的状态与错误；兼容旧配置和记录，不影响其他游戏，提供相应测试。 |

适配逻辑放在游戏适配器或独立服务中，界面通过状态模型调用。启动职责保持在 `GameLaunchOrchestrator`。结构和样式可参考 [ARCHITECTURE.md](ARCHITECTURE.md) 与 [UI_SPEC.md](UI_SPEC.md)。

### 源码构建

需要 Windows x64 和 .NET 10 SDK，SDK 放在 `.sdk/dotnet`。构建前取得官方 Node.js 24.19.0 Windows x64 `node.exe`，运行 `eng/prepare-maintenance-runtime.ps1 -NodeSource <路径>`。发布包已包含所需运行依赖。

```powershell
. .\eng\set-env.ps1
dotnet restore .\AsterLauncher.sln
& .\eng\build.ps1 -Configuration Debug -NoRestore
dotnet test .\tests\AsterLauncher.Core.Tests\AsterLauncher.Core.Tests.csproj --no-build --configuration Debug --logger 'console;verbosity=minimal'
```

打包使用 `eng/package-release.ps1`。工具、缓存和临时文件保存在项目目录，不修改全局环境变量。
